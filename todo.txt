 DECISIONS (agreed 2026-10-07)
--------------------------------------------------------------------------------
 D1  [REVISED 2026-10-07 r2] Code tooling is THIRD-PARTY:
       - Textual (gonzalezreal/textual, successor to MarkdownUI) renders ALL
         card text as markdown; code blocks highlighted with its bundled
         Prism.js (swift, python, java, cpp).
       - Runestone (simonbs/Runestone) + TreeSitterLanguages is the code
         EDITOR in the deck builder (line numbers, auto-indent, bracket
         pairs, no autocorrect or smart quotes).
     NFR-15 and Table 3 (services) in the .tex get amended to list them.
     Supersedes the hand-rolled tokenizer plan.
 D2  [REVISED r2] Card model is HYBRID:
       - prompt/answer are BLOCK markdown (lists, bold, inline `code`,
         short tables; fences are allowed and render, but aren't
         encouraged).
       - The main code example lives in the optional
         Flashcard.codeSnippet: CodeSnippet? {language, source} (UML 0..1),
         edited with Runestone and rendered by Textual as a fenced block.
       - Most cards have no code; the builder shows a collapsed
         "+ Add code" row.
 D3  Question (multiple-choice quiz bank) and Flashcard/FlashcardDeck stay
     SEPARATE models. Starter decks come from a NEW hand-authored
     codey/Resources/starter-decks.json, loaded via FlashcardFactory.
 D4  Sign-in is OPTIONAL. App is fully usable as a guest (local-first,
     NFR-08). Google sign-in enables cloud sync.
 D5  XP per correct quiz answer = tier base (Easy 10 / Medium 15 / Hard 20)
     + streak bonus min(5 × (streak − 1), 25). Max 45 XP per answer.
     (Replaces FR-30 "flat 10"; update the .tex.)
 D6  No Supabase project exists yet. Build it from scratch; the schema lives
     in-repo as SQL migrations (supabase/migrations) and is the source of truth.
 D7  Scope = everything the Sprint 2 doc marks Implemented / In progress,
     plus FR-22–31 (tiers, XP, levels). Could-haves are listed as stretch.
 D8  [REVISED r2] Navigation = HOME HUB with a Liquid Glass tab bar:
       - 3 tabs: Home | Decks | Quiz.
         .tabBarMinimizeBehavior(.onScrollDown) shrinks the bar to a pill
         on scroll.
       - .tabViewBottomAccessory shows "▶ Continue studying <deck> n/N"
         when a session is resumable.
       - Settings = PROFILE SHEET opened from the avatar button at the top
         right of Home: a native inset-grouped List.
       - Study and Quiz run as .fullScreenCover "focus mode", so the tab
         bar and accessory are hidden.
       - PracticeHomeView, AnalyticsDashboardView, and the Settings tab
         are removed.
 D8 r3 (2026-10-07, QoL pass): navigation de-duplicated.
       - Home = greeting + LevelCard + ONE "Up next" card (resume a
         session > new learner's starter deck > suggested quiz on the
         weakest pinned topic) + a compact "Your topics" list (→ quiz
         setup). Hub tiles, Home quiz Start/Choose, and deck Open/New
         were removed; those actions live in their tabs.
       - The tab-bar "Continue studying" accessory was REMOVED. Resume from
         the deck screen or Home's Up next card. The library long-press
         "Study" was removed (tap the tile → deck screen).
       - Starting a quiz has one path: topic → setup sheet → Start.
       - Profile: avatar on Home only.
       - Every study session and quiz is presented by RootView via the
         Router (one owner).
 D9  Tier gating applies to the QUIZ BANK and STARTER DECKS only.
     - Quiz question retires after 3 consecutive correct answers (FR-23/24).
     - Starter card retires when mastery reaches 5 (FR-18 "mastered").
     - User decks may carry an optional tier tag but are never locked.
 D10 Sync scope: user decks + cards (incl. snippets) + profile (display
     name, avatar, total XP). Per-question progress / unlocks stay local.

      would also wipe XP and progress. Seeding must become a non-destructive
      upsert of bundled content only.
   B3 Fake profile: the seeder inserts a profile with 1250 XP and a 7-day

      Hard-tier gate (FR-26). Seed a fresh profile at 0 XP.

   B5 XP rule in QuizSession (10 + 5×(streak−1), uncapped) matches neither
      FR-30 nor D5.
   B6 The quiz uses ALL topic questions, shuffled. FR-19 says 10 questions.
      The summary has no percentage (FR-20).
   B7 Difficulty is never read outside Question.swift and
      QuestionBankLoader (LSP findReferences). No tier logic exists.
   B8 Dark mode toggle: .preferredColorScheme is attached to SettingsView
      only. Tabs load lazily, so the setting doesn't apply until Settings is
      visited. It's also a 2-state toggle, but NFR-11 says "follow the
      system setting". Make it System/Light/Dark, applied at the root.
   B9 No deployment target in Project.swift (NFR-03 says iOS 17; now
      raised to iOS 26 per D11).
      SWIFT_VERSION = 5.
   B10 bundleId "dev.tuist.codey" is a template placeholder. Google OAuth
      needs a stable bundle ID.
   B11 QuizSession.recordAnswer swallows save errors (try?). Log them at
      minimum.
   B12 Hard tier is thin in the bank: DS has 1 Hard, DB has 2, Algo and OS
      have 3. With retirement, pools drain fast and FR-27's 70/30 mix can't
      be met. Content work in Stage 6.
   B13 FR-21 mentions OOP, but the bank has DS/Algorithms/OS/Databases.
      Either add OOP or change the FR text (Stage 12).
   B14 Corners (D19): Capsule() wraps multi-line content in
      QuizOptionRow:31/35, CodeyButton:54/58, TopicListView:92/95

 9.2 State pattern  (Services/Sync/DeckSyncState.swift — ALL states in this one file, R9)
 [x] protocol DeckSyncState { var kind: DeckSyncStateKind { get };
       var name: String { get }
       func onSave(_ deck) -> DeckSyncState
       func onEdit(_ deck) -> DeckSyncState
       func onPush(_ deck) -> DeckSyncState
       func onRemoteResponse(_ deck, _ result: RemoteResult) -> DeckSyncState
       func onResolve(_ deck) -> DeckSyncState
       func onDelete(_ deck) -> DeckSyncState? (nil = not allowed) }
     5 conforming structs: DraftingState, LocallyPersistedState,
     SyncingState, SyncedState, ConflictState.
     FlashcardDeck (context) persists syncStateRaw and exposes
     currentState { DeckSyncStateKind → struct }, plus save(), edit(),
     push(), resolve(), delete(), setState(_:).
     (Streamlining: SwiftData can't store a protocol existential, so we
      persist the enum raw value and rebuild the state object. The pattern
      is intact and the .tex should get a one-line note.)
 [x] Transition table = Fig. 7, exactly:
       (new) ──New Deck──▶ Drafting
       Drafting ──save, invalid──▶ Drafting (errors shown)
       Drafting ──save, valid──▶ LocallyPersisted (markDirty; enqueue upsert)
       LocallyPersisted ──edit──▶ Drafting
       LocallyPersisted ──push (online & signed in)──▶ Syncing
       Syncing ──push──▶ Syncing (no-op, already pushing)
       Syncing ──network drop/timeout──▶ LocallyPersisted (retry later)
       Syncing ──200 ACK──▶ Synced (lastSyncedAt = now)
       Syncing ──timestamp mismatch──▶ ConflictDetected
       ConflictDetected ──resolve (additive merge, markDirty)──▶ LocallyPersisted
       Synced ──edit──▶ Drafting
       LocallyPersisted | Synced ──delete──▶ (final) tombstone + enqueue delete
       Drafting | Syncing | ConflictDetected ──delete──▶ not allowed
